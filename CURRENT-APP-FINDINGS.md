# Problems found in the current (TypeScript) app

These are faults in the TypeScript app that came to light while it was being rebuilt in .NET. For each one the
list gives where it is in the TypeScript repository, what it does, and whether the .NET edition fixes it or keeps it.
Faults are kept where fixing them would change a number or a rule the owner has not yet decided on; those are left
for the owner. Other differences between the two editions are in [KNOWN-DIFFERENCES.md](KNOWN-DIFFERENCES.md).

## Security and data access

1. **A super user's "mark all read" clears every user's notifications.** *Where:* `src/app/(app)/notifications/actions.ts` (`markAllRead`) under the policies `notif_sel` and `notif_upd` in `supabase/migrations/0006_rls_performance.sql`. Both policies let a super user reach every row. *Effect:* when a super user opens Notifications, everyone's unread notifications are marked read. A super user's bell count and list also show other people's notifications. *.NET:* **fixed.** Each person's notifications are their own, a super user's included (the count, the list, mark-all-read and the marking on opening a review). Scheduled jobs still write anyone's notifications as the system.
2. **Held plans and daily loads can be read by any signed-in user.** *Where:* `plan_snapshots_read ... using (true)` in `supabase/migrations/0003_plan_snapshots.sql` and `daily_loads_read ... using (true)` in `0002_load_planning.sql`. *Effect:* any login can read any store's held plans and rosters (shifts, people's names, flags) and its daily load counts through the data API, outside the store scope that guards every other store table. *.NET:* **kept** (the same read rule), pending a decision. Every other store table is still read by store scope.
3. **26 tables are created by no migration.** *Where:* `supabase/migrations/*.sql` against the tables the code reads: break_rules, day_off_requests, day_plans, employee_availability, employee_leave, employee_restricted_tasks, employees, fixed_rosters, generated_shifts, labour_group_priority, labour_group_rules, non_op_categories, non_op_entries, non_op_subcategories, notifications, pay_rates, pay_settings, payroll_tax_rates, planned_blocks, quarter_hour_allocation, roster_audit, sales_overrides, shift_task_blocks, special_trading_hours, tab_visibility, weekend_markers. *Effect:* these tables exist only in the live database. A database built from the migrations cannot run the app, and their exact column types (for example whether the consecutive-day cap is a whole number) are not on record. *.NET:* **fixed.** The schema migrations create all 70 tables, their shapes reconstructed from the code, and a further migration inserts the reference rows.

## Wrong or misleading figures

4. **Analysis costs a relieving shift manager's hours at nothing.** *Where:* `src/lib/analysis/compute.ts`, `const rateRole = shift.role === "RSM" ? "SA" : ...`. Pay rates are keyed by position ("SA-FF", "SM-45-1", ...), and the rest of the app prices an RSM at "SA-FF" (`payKeyFor` in `src/lib/constants.ts`). *Effect:* an RSM shift adds hours but no wages, only the sole-manager allowance, so worked payroll, the average hourly rate and cost by position are understated. On the seeded test store, 55.8 RSM hours cost $63. *.NET:* **kept**, so the figures match, until the owner decides.
5. **The Team Members editor says the default notional hours are "contract ÷ 5", but the app uses contract ÷ 10.** *Where:* the help text in `src/app/(app)/setup/staff/StaffClient.tsx` (about line 833); the figure beside it is `contract / 10` (about line 709), as is the default in the reference data. *Effect:* the text is wrong. The number used (a fortnight's contract over ten working days) is consistent everywhere. *.NET:* **kept** word for word, for the owner to correct.
6. **Cost of leave depends on the database's row order when two leave entries overlap.** *Where:* `src/lib/analysis/compute.ts` reads `employee_leave` with no order and counts each person-day once, with the first row's hours. *Effect:* with overlapping entries of different day hours, the cost of leave can change between runs. *.NET:* **fixed order** (employee, start date, id).
7. **A plan edit that only changes a shift's role is not saved.** *Where:* `editPlanDay` in `src/app/(app)/plan/generate/actions.ts`: when the shift's start and end are unchanged, `{ ...prev }` carries the old held role. *Effect:* switching a shift between MGR, SA and JSA without resizing it is lost. *.NET:* **kept** (covered by a test), for the owner to decide.

## Dates and time zones

8. **The Sales fortnight arrows land a day early in Australia.** *Where:* `src/app/(app)/plan/sales/SalesClient.tsx` steps the fortnight with local-time `Date` and `toISOString()` in the browser. *Effect:* east of UTC the next "fortnight" starts on a Sunday. *.NET:* **fixed** (steps 14 calendar days, as the Non-Op page already did).
9. **Notification times are shown in UTC.** *Where:* `src/app/(app)/notifications/page.tsx` calls `toLocaleString("en-AU")` without a time zone on a UTC host. *Effect:* a 5 pm notification reads as 6 am. *.NET:* **fixed** (Sydney time, same format).
10. **The UKG export and printed roster give the right dates only on a UTC server.** *Where:* `src/app/api/export/ukg/route.ts` and `src/app/api/print/ukg-roster/route.ts` build the fortnight with `new Date(start + "T00:00:00")` (local time) and print it with `toISOString()` (UTC). *Effect:* on a server east of UTC every date is a day early. *.NET:* **fixed** (always the start date to start + 13 days, whatever the server's zone).
11. **The Dashboard's month table and Analysis's date range also depend on a UTC host.** *Where:* `src/lib/overview/compute.ts` (the month's dates and month end), `src/app/(app)/overview/page.tsx` (`shiftMonth`) and `src/lib/analysis/compute.ts` (the range loop), all local-time `Date` printed with `toISOString()`. *Effect:* correct only while the host runs in UTC. *.NET:* **fixed** (calendar dates).

## Pages that fail on an unexpected address or state

12. **A malformed `?period=` crashes Review.** *Where:* `src/app/(app)/plan/review/page.tsx` (for example month 13: `RangeError: Invalid time value`). *.NET:* **fixed** (opens the fortnight being planned).
13. **A `?month=` that isn't a date crashes the Dashboard.** *Where:* `shiftMonth` in `src/app/(app)/overview/page.tsx`. *.NET:* **fixed** (opens the current month).
14. **Sales with no store in scope crashes.** *Where:* `src/app/(app)/plan/sales/page.tsx` builds its dates from an empty start (Invalid Date). *.NET:* **fixed** (opens today's fortnight).
15. **The Floor Display shows "undefined NaN undefined" for a `?date=` that isn't a date.** *Where:* `src/app/floor/[token]/page.tsx`. *Effect:* an empty day with a broken heading. *.NET:* **fixed** (today is shown).
16. **The Roster page carries an unreadable `?date=` along as the selected date.** *Where:* `src/app/(app)/plan/roster/page.tsx`. *Effect:* an empty day. *.NET:* **fixed** (the address is ignored).

## Incomplete features and silent failures

17. **Load Planner "mark complete" is not stored.** *Where:* `markLoadComplete` in `src/app/load/[token]/actions.ts` ("Deliberately not persisted yet"). *Effect:* the completion shows only on the screen that pressed it and is gone after a refresh or on another device. *.NET:* **kept** (same behaviour).
18. **The Requests list stops at 1,000 rows.** *Where:* `src/app/(app)/setup/requests/page.tsx` reads through the data API, which returns at most 1,000 rows. *Effect:* a team with more requests on record loses the oldest from the list. *.NET:* **fixed** (every request is listed).
19. **Failed database reads show as empty data.** *Where:* most reads throughout `src/lib` and `src/app`. The database client returns `{ data: null, error }`, and the code carries on with `data ?? []`. *Effect:* a database outage can show zero figures or empty lists rather than an error. *.NET:* **fixed**, except where the old app made the fallback a rule (task priority, sub-task labels, audit rows, review notices, the notification count). Pages say plainly when their figures couldn't be read.
20. **Creating a store is not atomic.** *Where:* `src/app/(app)/admin/store-attributes/actions.ts` inserts the store, its attributes and its seven trading days separately, and deletes the store again if a later insert fails. *Effect:* if the clean-up also fails, a half-made store is left behind. *.NET:* **fixed** (one transaction).
21. **The EMSO roster check can raise duplicate alerts.** *Where:* `src/lib/emso/rosterCheck.ts` looks for an existing unread alert with `maybeSingle()`, which treats two or more matches as none. *Effect:* once two matching alerts exist, every run adds another. *.NET:* **kept** (same behaviour).
22. **Non-op minutes that aren't whole reach the database.** *Where:* the Add Non-Op sheet in `src/app/(app)/plan/non-op/NonOpClient.tsx` sends, for example, 30.5 minutes. *Effect:* the person sees the database's raw error, `invalid input syntax for type integer: "30.5"`. *.NET:* **kept** (the same message, now shown before saving).
23. **The upload page shows the old file after the type changes.** *Where:* `src/app/(app)/admin/uploads/Uploader.tsx` clears its own state but leaves the browser's file box showing the previous file. *.NET:* **fixed** (the box is cleared).
